# 経営実務 赤ペン注釈プラン作成仕様

会計実務・監査実務で確立した方式と同じ流儀で、経営実務のテキストに講義内容を反映する。
1プラン = 1行1オブジェクトのJSONL。**pageはPDFページ番号(1始まり)**。
章↔ページの対応は keiei_structure.md の表を使う。

## 対象PDFとダンプ
- IT以外: 経営_IT以外_インク統合.pdf / ページダンプ pages_kn/pNNN.txt
- IT: 経営_IT_インク統合.pdf / ページダンプ pages_ki/pNNN.txt
※インク統合版は元教科書と同じページ構成で、講師の書き込み(手書き・マーカー)が既に載っている。
  **書き込みで既に示されている内容をコメントで繰り返さない**(重複はムダ)。音声から得た
  「書き込みだけでは分からない説明・理由・出題予想」をコメントにする。

## 出力形式
```json
{"page": 31, "type": "highlight", "search": "静態的安全性分析", "occurrence": 0}
{"page": 31, "type": "underline", "search": "期末残高のみを用いて算定する"}
{"page": 31, "type": "margin", "search": "自己資本比率", "text": "R5出題"}
{"page": 31, "type": "comment", "search": "短期の安全性分析", "text": "整理済みコメント本文"}
{"page": 31, "type": "comment", "text": "ページ全体に関わるコメントはsearch省略可"}
```
- **highlight** = 赤マーカー(覚えるべき指標名・定義・要件)
- **underline** = 赤下線(その節で最重要の一文)
- **margin** = 欄外の短い赤文字(20字以内)
- **comment** = ページ右の帯に赤字で直接印字される解説。**主役**
- **badgeタイプは使わない**(重要度A/B/Cの説明メモは不要というユーザー指示)

## commentの書き方
1. 講師の発言を**逐語で並べない**。同じページ・同じ論点の発言は統合し、論点ごとに整理して書く。
   1ページ1〜3個、1個40〜220字、1ページ合計350字(最大450字)
2. 優先する内容:
   - 計算式・指標の**覚え方**(分母分子の意味、なぜその式か、混同しやすい指標との対比)
   - 背景の考え方(なぜその分析をするのか、実務での使われ方)
   - 出題予想・学習方針(捨ててよい/確実に取る/計算を回す 等)
   - 講師の実務経験談のうち理解を助けるもの
   - 例題・過去問については解き方の着眼点と答案の骨子
3. 教科書に既に書いてあることの単純な言い換えはコメントにしない
4. 「講師メモ」前置き・タイムスタンプ・重要度ランクの説明は書かない。だ・である調
5. 教科書と講義にある内容のみ。創作しない

## アンカー(search)のルール(厳守)
1. 対象ページのダンプ pages_xx/pNNN.txt の**1行内に実在する連続文字列**(8〜25字)をコピー。
   **出力前に必ずgrepで実在確認**。数式・記号混じりの行は避け、日本語の連続部分を選ぶ
2. 長い文のhighlightは行単位に分割。複数回出る文字列はoccurrence(0始まり)
3. アンカーを特定できないcommentはsearch省略(ページ先頭に置かれる)

## 計算問題の扱い(経営実務の特性)
経営実務は財務分析・企業価値評価の**計算**が中心。数値例・例題のページでは、
「どの数字をどこに入れるか」「引っかけポイント(期中平均か期末か、税引後か等)」を
commentに簡潔に書く。式そのものの再掲は不要。

## whisper誤変換の正規化(経営系で頻出)
終了考査→修了考査、経営実務、財務諸表分析、ROE/ROA/ROIC、DCF法、WACC、
エンタープライズバリュー、のれん、EBITDA、コーポレートガバナンス・コード、
ITガバナンス、統制、監基報 等。文脈で判断し教科書用語に直す。壊れて意味が取れない箇所は使わない。
