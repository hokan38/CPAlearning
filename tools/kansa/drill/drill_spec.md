# 監査論ドリル 節別フラグメント作成仕様

## 目的
監査実務テキスト（基本論点編1・2、修了考査対策編1〜3）の内容を「覚えにくい教科書」から
**問題を解きながら覚えられる問題集**に変える。テキストの見出しに付いた重要度〔Ａ〕〔Ｂ〕の
見出しを**すべて**問にする（〔Ｃ〕は収録しない）。並びは**教科書の記載順**。

## 素材
- テキストのページダンプ：`<TB>/<book>/pNNN.txt`（NNN＝PDFページ番号、1始まり）。book は k1〜k5。
  - k1=基本論点編1（第1〜3章） k2=基本論点編2（第4〜6章） k3=修了考査対策編1 k4=修了考査対策編2（改正）
    k5=修了考査対策編3（倫理規則・法規）
- 表が崩れて読めないページは画像で確認してよい：
  `python3 -I -c "import pymupdf;d=pymupdf.open('<TB>/k1.pdf');d[174].get_pixmap(dpi=110).save('<作業dir>/p175.png')"`（index＝PDFページ−1）を Read で見る。
- **素材はテキストだけ。テキストに書いていないことは一字も足さない（創作・一般知識での補足は禁止）。**

## 出力
節ごとに1ファイル：`tools/kansa/drill/frag/<book>_<章>-<節2桁>.html`（例 `k1_3-06.html`、序章や付録は `k5_A-01.html` のように任意の記号でよい）。
HTML断片のみ（<html>/<head>/<style> は書かない）。
```html
<section class="chap" data-book="k1" id="k1_3-06">
<h1 class="chap">第3章 第6節　重要な虚偽表示リスクの識別と評価<small>基本論点編1</small></h1>
<div class="item" data-rank="A" data-pdf="175" data-head="５．定義">…</div>
…
</section>
```

## 1問(.item)の形（属性の順番・クラス名を厳守）
```html
<div class="item" data-rank="A" data-pdf="175" data-head="５．定義"><div class="th">定義（関連するアサーション／重要な取引種類等）<span>③-6-5</span></div>
<div class="q"><b>問</b>監査基準報告書315における「関連するアサーション」「重要な取引種類，勘定残高又は注記事項」の定義を述べなさい。</div>
<div class="a"><span class="l">解答</span>
<p><b>関連するアサーション</b>　取引種類，勘定残高又は注記事項に係るアサーションのうち，<k>重要な虚偽表示リスクが識別されたアサーション</k>をいう。なお，アサーションが「関連するアサーション」であるかどうかの判断は，関連する内部統制を考慮する前に（<k>固有リスクのみを考慮して</k>）行われる。</p>
<p><b>重要な取引種類，勘定残高又は注記事項</b>　関連するアサーション（重要な虚偽表示リスクが識別されたアサーション）が<k>一つ以上存在する</k>取引種類，勘定残高又は注記事項をいう。</p>
</div>
<div class="pt"><b>出典</b>基本論点編1 ③-6-5（監基報315 11項(5)(8)，A218項）</div></div>
```
- `data-rank`：その見出しのテキスト上の重要度（〔Ａ〕→A、〔Ｂ〕→B）。子見出しに別の重要度が付いていれば子見出しの重要度に従う。
- `data-pdf`：解答の文章があるPDFページ番号。2ページにまたがるときはカンマ区切り（`175,176`）。
- `data-head`：テキストの見出し文字列をそのまま（番号含む。例「５．定義」「（２） 監査人の対応」）。
- `.th`：論点名（短く。見出し名ベースでよい）＋ `<span>` に印字ページ（ページ下部の「－ ③-6-5 －」の中身。対策編は「①－12」等。ない場合は省略）。
- `.pt`：`<b>出典</b>` テキスト名＋印字ページ（＋テキストに書いてある根拠規定）。

## 問の作り方（ここが一番大事）
1. **〔Ａ〕〔Ｂ〕の見出し1つにつき原則1問**。見出しの中に独立した論点（定義表・要求事項の列挙・趣旨・事例）が複数あるときは2〜3問に分けてよい。小見出しごとに機械的に分けすぎない。
2. 問題文は修了考査の記述問題の文体で1〜2文。テキストの内容から「何を書けば正解か」が一意に決まる問いにする。型は次のいずれか：
   - 列挙型「〜を○つ挙げなさい」「〜の要件を述べなさい」（数がテキストで決まっているときは数を明示）
   - 定義型「〜とは何か，定義を述べなさい」
   - 要求事項型「〜の場合，監査人は何を実施しなければならないか」
   - 趣旨・理由型「〜はなぜか」「〜の趣旨を述べなさい」（テキストに理由が書いてあるときだけ）
   - 対比型「AとBの相違を述べなさい」（テキストに対比表があるとき）
   - 事例型：テキストに例題・過去問（問題文＋解答例）があるときは、その問題文と解答例をそのまま使う
3. **解答はテキストの文章をそのまま写す**（言い換え・要約・語尾の変更・つなぎ言葉の追加は禁止）。
   使ってよいのは、文の取捨選択（問に関係ない文を省く）、順番どおりの抜粋、`<p>` `<ol>` `<ul>` `<li>` `<b>` `<table>` による整形、表の見出し語を `<b>…</b>` で前に出すことだけ。
   箇条書きの記号（・①(1)など）はテキストどおり残してよい。
4. `<k>…</k>` は採点で必ず入れるべき語句（キーワード）だけに付ける。1段落・1項目に0〜2か所。
5. 解答の長さの目安：A は答案にそのまま書ける分量（100〜400字）、B は骨子（60〜250字）。長い説明は問を分ける。
6. 表（左右2列の定義表・比較表）は崩れていることが多い。画像で確認して正しい対応関係で写すこと。
7. 「重要」「ポイント」「試験対策上」など講師的なメタ文はテキストにあっても解答に入れない。

## 検査（必須）
各ファイルを書いたら
`python3 -I tools/kansa/drill/check_kfrag.py tools/kansa/drill/frag/<file>.html <TB> <節の開始PDFページ> <終了PDFページ>`
を実行し、**指摘0件**にしてから次へ進む。
- 「一致率」の指摘＝解答にテキストにない文字列がある → テキストどおりに直す（data-pdf のページ番号違いもこれで出る）。
- 「未収録の見出し」＝その範囲の〔Ａ〕〔Ｂ〕見出しが問になっていない → 問を追加する。見出しでないもの（表中の〔Ａ〕等）を拾っている誤検出なら、`data-head` にその文字列を含めた問を作るか、最終報告でその旨を書く。
